# Net-to-Serial

*[English version: README.md](README.md)*

Ещё один шлюз, который передаёт сырой поток октетов между TCP-соединением и последовательным
портом машины, на которой он работает.


###	NaPi World
Проект разрабатывается и сопровождается командой NaPi Lab, основное тестирование идёт на
промышленных одноплатных компьютерах NaPi на процессорах Rockchip.

####	Платы NaPi

Если вы ищете надёжную аппаратную платформу для промышленной эксплуатации net2serial,
посмотрите линейку плат NaPi:

Добро пожаловать в NaPi World (https://github.com/napilab/napi-boards)!

Сейчас доступны:

- NAPI2 — RK3568J, RS-485 на плате, Armbian
- NAPI-C — RK3308, компактная, промышленного исполнения


###	Введение

Простой шлюз TCP → последовательный порт (Ethernet-to-Serial, Network-to-Serial): передаёт
поток октетов от удалённого TCP-клиента к локальному последовательному устройству. Ничего не
интерпретируется: что клиент набрал — уходит в устройство как есть, что устройство напечатало —
приходит обратно как есть. Именно поэтому работает одинаково с приглашением логина, с
загрузчиком и с двоичным протоколом.

Типичные применения:

 - консольный сервер для коммутаторов, маршрутизаторов, ПЛК и старого железа
 - удалённый доступ к приборам с интерфейсами RS-232 и RS-485
 - развитие навыков программирования: ввод-вывод на портах RS-232 и RS-485
 - строительный блок для двунаправленных шлюзов TCP → RTU и RTU → TCP


###	Основные возможности и достоинства

  - прозрачный поток октетов в обе стороны, ничего не интерпретируется
  - несколько последовательных портов и несколько TCP-портов в одном процессе
  - дисциплины управления потоком: NONE, XON/XOFF (программная), RTS/CTS (аппаратная)
  - специфика сигналов RS-232 и RS-485 (управление направлением средствами ядра)
  - один процесс с многопоточной архитектурой: по потоку на активную сессию
  - один клиент на порт за раз: второму клиенту выдаётся внятный отказ вместо молчаливого
    перемешивания его октетов с чужими


###	Надёжность, ресурсоёмкость и производительность

**Данные не теряются по дороге.** Частичная запись в медленную последовательную линию
продвигает кольцевой буфер на фактически записанное количество, поэтому хвост вставленного
блока никогда не выбрасывается. Два направления развязаны парой кольцевых буферов, а
запрашиваемые события `poll()` выводятся из состояния этих буферов на каждом круге — это даёт
честное встречное давление той стороне, которая быстрее, и ни один октет не читается раньше,
чем появится место, куда его положить.

**Ни одна ошибка не молчит.** Каждый отказ порождает кодированное сообщение журнала
(`%N2S-E-DEVOPNERR`, `%N2S-E-LINKDOWN`, `%N2S-W-DEVBUSY`, ...), которое называет конкретную
причину: отказавший системный вызов, его `errno`, допустимый диапазон неверно заданного
параметра. Журнал спроектирован так, чтобы искать в нём по коду и чтобы поиск неисправности
был чтением, а не гаданием — см. руководство пользователя, глава 6.

**Ни зависаний, ни циклов активного ожидания.** Отказ последовательной ноги (выдернутый
USB-адаптер) или обрыв соединения обнаруживаются через `POLLERR`/`POLLHUP`/`POLLNVAL` и
закрывают сессию с диагностикой, а не крутят процессор. Таймер простоя закрывает только
по-настоящему простаивающие сессии: любой трафик его сбрасывает, поэтому оператора, работающего
в консоли, никогда не отключит на полуслове.

**Малый след.** Один процесс; из зависимостей времени выполнения помимо libc — только
libconfig. Нигде нет тикающих в фоне таймеров: всё ожидание построено на `poll()`, поэтому
простаивающий шлюз с подключённым клиентом почти не потребляет процессор. Поток существует
только на *активную* сессию и освобождается сразу после отключения клиента — утечек потоков и
памяти нет, подтверждено прилагаемым стендом и сборками под ASan/UBSan. Благодаря этому шлюз
комфортно живёт на малых промышленных одноплатных компьютерах линейки NaPi (RK3308, RK3568J) —
и на чём угодно крупнее.

###	Установка

Шлюз зависит от двух пакетов: **libconfig** (разбор файла настроек, берётся из дистрибутива) и
**StarLet** (набор UTILITY$ROUTINES, ставится из исходников как пакет CMake). Полная
последовательность от чистой системы до работающего шлюза:

####	Шаг 1. Установить средства сборки

```
$ sudo apt install build-essential cmake pkg-config libconfig-dev
```
(в дистрибутивах на основе RPM: `sudo dnf install gcc make cmake pkgconf libconfig-devel`)

####	Шаг 2. Установить пакет StarLet

```
$ git clone https://gitlab.com/SysMan-One/utility_routines
$ cd utility_routines
$ mkdir build && cd build
$ cmake ../ -DCMAKE_BUILD_TYPE=Release
$ make -s
$ sudo cmake --install .
```

Пакет ставится в `/usr/local`: библиотека `libstarlet`, публичные заголовки и конфигурация
пакета CMake (после этого становится доступен `find_package(StarLet)`). Чтобы установить в
другой префикс, используйте `sudo cmake --install . --prefix /opt/starlet`, а на шаге 3
передайте шлюзу `-DCMAKE_PREFIX_PATH=/opt/starlet`.

####	Шаг 3. Собрать шлюз

```
$ git clone <URL репозитория>
$ cd net2serial
$ mkdir build && cd build
$ cmake ../ -DCMAKE_BUILD_TYPE=Release
$ make -s
```

Типы сборки: `Release` (эксплуатация), `Debug` (символы, трассировка), `Asan` (санитайзеры
адресов и неопределённого поведения, для разработки).

####	Сборка с musl (OpenWrt, Alpine, встраиваемые образы)

Шлюз собирается и работает и с библиотекой **musl** — это обычный случай для образов на основе
OpenWrt и Alpine на промышленных платах. В комплект входит toolchain-файл:

```
$ cmake ../ -DCMAKE_TOOLCHAIN_FILE=../cmake/musl.cmake -DCMAKE_BUILD_TYPE=Release \
	-DCMAKE_PREFIX_PATH=<префикс musl>
$ make -s
```

Зависимости (StarLet и libconfig) тоже должны быть собраны под musl и установлены в этот
префикс; укажите `PKG_CONFIG_LIBDIR` на его `lib/pkgconfig`, чтобы подхватился musl-вариант
libconfig, а не системный.

Одна особенность musl, которую берёт на себя toolchain-файл: musl поставляет собственные
заголовки, но не заголовки ядра (`linux/serial.h`, `asm/ioctls.h`), поэтому каталоги заголовков
ядра добавляются через `-idirafter` — так заголовки musl всегда выигрывают, а `/usr/include`
просматривается только ради того, чего в musl нет. Обычный `-I` отравил бы сборку заголовками
glibc.

####	Шаг 4. Установить шлюз

```
$ sudo make install
```

Что куда попадает:

| Что | Куда |
|-----|------|
| Бинарник `net2serial` | `/usr/local/sbin/` |
| Файлы конфигурации | `/usr/local/etc/net2serial/` |
| Документация и эталонные копии конфигов | `/usr/local/share/doc/net2serial/` |

Файлы конфигурации ставятся **только если их нет**: повторный `make install` (обновление)
никогда не затирает настроенную рабочую конфигурацию — такие файлы отмечаются в выводе как
`Keeping the existing ...`.

####	Шаг 5. Настроить и запустить

```
$ sudo vi /usr/local/etc/net2serial/net2serial_settings.conf
$ /usr/local/sbin/net2serial /settings=/usr/local/etc/net2serial/net2serial_settings.conf
```

####	Деинсталляция

```
$ cd net2serial/build
$ sudo make uninstall
```

Удаляется всё, что поставил `make install`, кроме файлов конфигурации в `etc/net2serial/` —
настроенная рабочая конфигурация переживает деинсталляцию всегда.


### 	Быстрая настройка

Опция конфигурации — строка текста, начинающаяся с «-» или «/», регистр не имеет значения:

`/<имя_опции>=<значение>`

или

`-<имя_опции>=<значение>`

Пример:

`-logfile=/tmp/net2serial.log`

##### Опции командной строки

| Опция			|  Описание
| ------		| ------------------------------------------------------------
| trace			| Включить подробную диагностику. Полезно при отладке и поиске неисправностей.
| logfile=\<fspec\>	| Задать файл для вывода журнала
| logsize=\<число\>	| Ограничить размер файла журнала
| settings=\<fspec\>	| Задать файл конфигурации сети и последовательных устройств


##### Параметры файла настроек
Смотрите пример файла настроек как справочник параметров и правил конфигурирования, либо
руководство пользователя (глава 3) — там описан каждый ключ с допустимым диапазоном значений.


###	Тестирование

В комплект входит самодостаточный функциональный стенд: он создаёт пару псевдотерминалов,
запускает эмулятор последовательного устройства, поднимает шлюз и проверяет сквозную передачу,
объёмную передачу 60 000 октетов (путь частичной записи), владение портом, потребление
процессора на простое и отсутствие утечек потоков.

```
$ python3 tests/bench.py ./build/net2serial
```
